# 只读 Worker 与项目记忆

## 只读子任务

在项目会话中给予项目只读或读写权限。可用两个 UTF-8 文本文件试跑，例如“把 a.txt 的结论和 b.txt 的数据分别交给独立 Worker 核对，最后按文件汇总并注明证据”。主模型调用 `delegate_readonly` 后，宿主按两个子任务各自的清单读取文件。回复下的「执行记录」会显示子任务状态、原文件指纹、读取范围、回执编号和下载报告入口。

主模型选择子任务的目标、角色、输入片段和验收要求。每个 Worker 发起独立模型请求，只获得自己的输入及回执，不加载主聊天历史、项目记忆或其他 Worker 的材料。宿主只读当前项目的普通相对文件路径，每个 Worker 最多读三个片段。结果由主任务复核，报告保存在运行产物区。

每批最多两个 Worker，每轮最多四个。单批限 45 秒，每个 Worker 至多一次模型 HTTP 请求和 1200 输出 tokens。并发和读文件、推理用量记入根任务，调度前为主任务保留至少一次汇总调用。缺文件时记录阻塞，另一个 Worker 继续。停止父任务会取消在途调用，已保存的回执和报告仍可查看。服务退出后，未完成的子任务从父运行状态恢复为中断。

`GET /api/tools/contract` 的 `workers` 提供工具契约。`GET /api/runs/:id/workers` 返回同一运行的子任务、状态、读取回执和产物，`GET /api/runs/:id/budget` 提供共享预算账本。

## 项目记忆

在侧栏项目名旁点「记忆」，可搜索、新增、编辑、停用和删除当前项目的记忆。用户偏好直接由用户确认。项目事实需填写项目内的来源文件，保存时记录文件 SHA-256。用户负责核对事实文本与来源的对应关系。

每轮最多选取四条触发词匹配的启用记忆。事实使用前重新读取来源文件并核对指纹，来源变化或不可读时只向模型提供提示，事实内容不进入本轮上下文。记忆是参考资料，文件权限和验收条件仍由当前任务决定。切换会话绑定的项目时，其他项目的文件上下文不会进入后续请求。

接口在 `/api/projects/:projectId/memories` 下，GET 列出，POST 新增，PUT 编辑，PATCH 启停，DELETE 删除。单条记忆的 `/verify` 可检查来源状态。编辑、启停和删除都需携带当前修订号。

## 验收

`node --test collaboration.test.mjs` 通过本机 HTTP 模型夹具对照单 Agent 与 Worker 模式。在同一份两文件任务中，两者均给出指定结果，模型调用分别为 2 次和 4 次。另验证越界与预算拦截、服务商 429 时保留另一 Worker 的证据、父任务停止传播，以及项目记忆的失效和隔离。该对照测量执行链路及调用开销，模型效果仍需用实际任务评估。
