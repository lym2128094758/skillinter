# 根任务预算与上下文

每个会话轮次分配一个 `rootRunId`，与本轮运行 ID 相同。主聊天、内部数据预检、材料读取和技能检索共用账本。独立预检以自己的运行作为根，隔离文件对照的每一组各有同样的固定限额。

| 项目 | 默认值与行为 |
| --- | --- |
| 模型请求 | 主聊天用设置里的 1–12 次。每个 HTTP 请求都计数，包括供应商重试、截断重试和引导后重发。 |
| 总时间 | 主聊天 900 秒。独立数据预检和材料检查使用各自的工作流时限。 |
| 工具 | 主聊天 128 次，含经入口调用的工具和内部预检步骤。引擎尝试另列，同样有界。 |
| 并发 | 同一根任务的模型、工具、引擎分别最多同时 2 次。父工具等待内部步骤时继续占用自己的工具槽。 |
| 单次上下文 | 默认估算上限 131072，已知模型容量更低时取较小值，并为本次输出预留空间。 |
| 累计模型用量 | 默认估算输入 1200000、输出 98304。供应商返回用量后按实际值结算。缺失字段继续按预留量占用。 |

根限额位于 `config.yaml` 的 `runBudget`。模型代理在发送前同步预留，在返回、超时、拒绝或取消后结算。供应商的未知用量与实际已报告用量分列，预留量不代表账单费用。持久化使用同一 SQLite 事件流。进程退出后，尚未结算的请求保留为中断及用量未知。服务重启不会自动重发。

模型请求优先保留首条系统契约、当前目标、运行中收到的引导和最新工具回合。工具回合整体保留或整体省略，避免孤立的工具调用或响应。最近八轮历史中，超预算的整轮转为有来源的原文摘录，空间仍不足时只记录省略来源。工具结果默认超过 8192 字节便发送有界摘录，保留回执编号、原文指纹和大小。执行记录仍能展开完整结果。输入估算采用消息和工具 JSON 的 UTF-8 字节数，图片另外按每张 4096 估算单位预留，均不是供应商分词结果。

- `GET /api/runs/:id/budget` 返回已知实际用量、未知请求数、占用额度和逐次预留、结算记录。升级前的历史运行返回 `data: null`。
- `context_snapshot` 事件保存实际发送的消息与工具指纹、估算和输出预留，列出被省略的历史运行和回执。它不保存新的图片副本。
- `GET /api/skill-intelligence/contract` 导出检索、计划建议、公开发现、改进提案的接口和错误码。主聊天的 `search_skills` 已使用本地适配器。宿主检查快照、技能引用和来源范围，记录耗时、引擎版本及回退原因。外部 SkillNet 传输和 Worker 由后续阶段接入。

模型连通性探测、提示词优化及技能工坊的独立文本生成仍沿用各入口的请求时限。预检报告的计数按规划层记录，供应商 HTTP 尝试以根账本为准。涉及自动重试、运行中引导或根预算中止的记录可查执行轨迹，原样回放以录制文件中的可回放标志为准。

使用 `npm run check:budget` 验证供应商重试计数、并发预留、取消、上下文裁剪和检索回退。主聊天端到端回归另核对内外层模型请求共享同一个运行账本。
