# 方向三：开放赋能智能体

以用户提供的赛题完整文本为准：必须使用书生大模型，Harness 可自选。Agent Skills、MCP、A2A、多智能体、上下文工程和记忆等为可选技术，不要求同时完成。当前开发调试按用户要求使用 `deepseek-v4.1-flash-1017`；最终展示使用书生模型前须实跑同一任务，不能只替换界面标签。

目标是让用户给出目标和材料后，发现适用方法、按依赖执行、核验产物，并将经过独立验证的方法复用到下一次任务。首个应用收口为科研和工程项目交接、复现准备及交付材料核对，不限制材料格式。

| 环节 | 当前机制 | 当前证明范围 |
| --- | --- | --- |
| 理解和计划 | 主聊天模型与 update_plan | 模型可提交及修订计划，不强制简单任务建计划。 |
| 技能发现 | 本地检索及可选 SkillNet 引擎 | 只执行已安装且可见技能；外部发现先预览审核。 |
| 关系编排 | 统一 UUID 注册表及本轮关系快照 | depend_on 决定前置顺序；互补和替代不自动变成依赖。此项已实现，旧截图“来源尚需统一”已过期。 |
| 工具执行 | 按会话权限读取和修改项目材料 | 实际回执关联技能及计划；测试命令须通过已有确认入口。 |
| 验收交付 | 冻结 delivery、重读产物及引用核验 | 仅证明声明条件和引用满足，不追认语义结论或真实业务收益。 |
| 经验改进 | 来源线索、候选、独立配对及审核发布 | 真实候选已生成；上轮配对中止，尚未证明改进或新批次复用。 |

## 当前框架收口

按用户最新要求暂停示例，优先打通主聊天的技能执行、产物验收和经验候选。`run-outcome.mjs` 为 HTTP 历史及实时聊天提供同一份状态规则：回复结束、交付通过、交付失败、待核验和未收尾分开显示。有可分析记录的失败/停止任务也可提炼草稿，不能因此绕过独立对照和发布门槛。当前默认模型为 v4.1。

## 可选验收脚本（暂不执行）

在 SIH 已启动且 API 可用时运行：

```powershell
node scripts/check-project-delivery.mjs
```

默认使用 v4.1。在本机 3095 的正常主聊天入口创建一个项目范围的合成示例，安装“材料清点”和“交付核对”两个方法，声明后者依赖前者。模型核对真实目录与交付清单，写出清点结果和报告；宿主核对原始输入、缺项、真实应用顺序及产物验收。来源材料刻意包含一个缺项，不能把报告未判 ready 当成执行失败。

示例会出现在侧边栏，标题为“项目交付核对 · 完整示例”。材料和 acceptance.json 默认写入 `D:/gpt/outputs/skillinter-project-delivery/`。整个模型任务最多 60 秒，超时停止并保留未完成记录；合成示例不用于宣称真实场景准确率或效率提升。最终书生联调可将第一个参数替换为模型目录实际提供的书生 ID，仍沿用同一判据。

先把这条应用链路跑通并复用，再扩展多智能体角色和更多场景。保持现有图谱和界面，当前不新增装饰性页面。
