# Harness H1–H10 自检

机器契约见 [tool-registry.json](tool-registry.json)。在线实例提供 `GET /api/tools/contract` 和 `GET /api/audit/contract`。调用时传工具名和 `parameters` 定义的 JSON，按 `returns` 处理结果。宿主处理授权，不从请求正文或模型生成的文字取权限。改过配置、工具或提示后运行 `node scripts/export-contracts.mjs`、`npm run check:contracts`、`npm test`，再执行带真实模型的复核。

| 编号 | 判定与检查 |
| --- | --- |
| H1 | 共 20 个工具定义，包括 4 个文件工具、5 个主会话技能工具、1 个计划工具、5 个技能运行工具、1 个项目测试工具和 4 个预检内部工具。每个均有名称、参数与返回 schema、错误码、时限、幂等性和鉴权，注册表与实际输出用同一份定义校验。 |
| H2 | 结果键依次为 `ok`、`data`、`error`。成功时错误为 `{code:"OK",message:""}`，失败时 `data=null`。目录条目按 UTF-16 路径字典序排序。易变字段见各工具的 `volatile` 列表。 |
| H3 | 自检触发不存在、越界、无权限、符号链接、空目录、截断、非法 UTF-8 和超限。空目录、空工作区和截断是成功结果的固定 `data.notice`。 |
| H4 | 深度、隐藏、过滤、上限和字典序均在 registry 定义。默认路径 `.`、不递归、递归深度 3、隐藏点号项、无筛选、上限 300，不跟随链接。 |
| H5 | 按零起始 offset 分页读 UTF-8，默认 100 行。返回实际范围、总行数、末行是否被裁剪和原始 SHA-256。 |
| H6 | 文件和工具内容属于数据，不授予权限。用干净与含注入的 README 对照，并检查工具日志与有无写入副作用。 |
| H7 | 数据预检规划器和普通会话默认只读。只读会话没有写入、删除、命令或联网工具，服务端也拒绝伪造的写工具。CSV 技能只能读取同一会话的原始附件。项目测试必须绑定项目并具备写入权限，每次由本机用户确认，测试代码使用当前系统账号运行。自检覆盖伪造或重复确认、拒绝、引导撤回、停止和重跑。 |
| H8 | 提示词引用实际工具和权限，对应服务端检查。每次模型响应最多触发 8 个工具调用，按顺序执行。主会话与嵌套预检共用本轮模型调用额度，停止和补充引导可进入嵌套规划。仅承诺将执行而没有工具回执的回复会继续执行或以预算耗尽终止。 |
| H9 | 明确的读取、列目录、权限问答走宿主确定性路径。其他会话由模型理解任务，读取结论来自工具观测，缺信息写“未提供”，推测须标注。 |
| H10 | 用两个行为不同的测试适配器验证同一契约。真实模型使用下列命令核对实际回复模型名、同一系统提示、干净及对抗读取输出，以及是否尝试越权。 |

`npm run check:models -- minimax-m3 deepseek-v4.1-flash-1017`

真实检查中的 H3、H4、H7、H9 由宿主直接完成，并记录零模型调用。H5 与 H6 依赖模型理解文件。这两项比较读到的业务值和授权内动作，服务商文本排版或合法截断提示不进入业务值判定。结果写入 `.skillinter/evaluation/harness-live-models.json`。

`GET /api/tools/contract` 的 `tools` 为文件工具，`skills` 包含主会话的检索、计划、技能执行和 `run_project_tests`。有可用的已发布技能时才向模型提供技能加载及运行工具，只能读取本轮固定技能版本；包资源检查不扩大任务文件权限。`GET /api/audit/contract` 保留预检内部契约。两者一并导出至 `tool-registry.json`，`npm run check:contracts` 覆盖这些契约并核对导出文件与在线接口。每轮实际给模型的工具按会话权限筛选。

纯读取和检索的排序与返回保持稳定。主会话预检在同一轮缓存相同参数，JSON 键顺序不区分两次请求。跨轮会重新规划，模型编排结果的幂等性明确为 false，离线重放使用固定源码和录制响应。每轮只执行一个不同的预检目标，避免混用报告和图谱轨迹。
