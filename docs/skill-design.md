# 数据预检的技能选择与执行证据

实验室数据整理人员收到一批表后，需要核对字段含义、单位和数值规则。一个误判的列名或单位会让下游用错误口径读数。Skillinter 根据目标和原表筛选可执行的技能，由模型决定语义映射与可选步骤，用本地工具逐行检查，给出可点击到原始记录的问题清单。缺单位时会暂停并要求补充。当前实测统一引用 [README 回归基线表](../README.md#公开表回归基线)，包含失败样本。人工耗时和错检率仍需实测。技能注册和证据回放沿用了原 SkillNet 的设计思想。

**技能 = 工具 + 适用条件 + 版本 + 前置依赖 + 产物契约。** 工具负责执行一次操作。技能进一步说明它在什么条件下能进入计划，以及结果能交给哪个后续步骤。注册表由 `GET /api/audit/skills` 提供。

~~~mermaid
flowchart LR
  A[用户目标和 CSV] --> B[宿主读表头与样本]
  B --> C{规则筛选技能}
  C -->|单位证据不足| D[空选并列出缺失证据]
  C -->|候选存在| E[模型分别决定映射和可选统计，宿主按契约组装依赖]
  E --> F[宿主验证计划和产物依赖]
  F --> G[工具执行并写事件]
  G --> H[报告、计划和图谱投影]
~~~

筛选是确定性的。目标要求单位时，原表必须有至少一个单位兼容的列名，使用 `g`、`mg` 等符号。仅通过筛选还不能确定语义映射，执行器会再检查被选列、原文证据和换算关系。表头只有「净重」却要求统一为 mg 时，预检读取一次表头，输出候选为空、缺失项及原表链接，模型调用为 0。

| 链路 | 产物交接 |
| --- | --- |
| 普通检查 | 表头和样本 → 普通字段映射 → 逐行类型、缺失、范围检查 |
| 单位检查 | 表头和样本 → 带换算系数的字段映射 → 按目标单位逐行校验。原始列统计可作为独立支路，从表头检查后的同一份 CSV 取数据。 |

筛选事件、采用计划和执行回执写入同一条日志。回执包含实际输入和产物指纹。`plan.json` 导出注册表版本、每版计划、技能版本和图谱投影。图谱只标记该版采用的节点，用回执区分已完成、失败和未执行。球体沿用原目录节点、布局与关系，本地技能通过目录节点做定位锚点；球体不参与筛选或执行。实际依赖列在图谱下方。前一版失败和重规划仍可在执行记录查看。

## 候选规则与冷启动

首批没有已启用的复用规则。由模型在筛选后的技能中提出映射，人核对来源列、字段含义和适用范围后，才能形成候选。验证前固定数据来源、表头、目标 schema、适用单位和校准文件指纹。待验证批次必须与校准记录分开，任何字段不匹配或来源不明都回到原流程。

最小准入门槛为至少 3 个未参与制定的正向标注批次及 5 个负向批次。逐批和冻结标注核对，正向批次必须全部通过，每个要求的字段均应映射正确，负向误启用为 0。通过后进入人工审核。这是针对实际提交样本的验收门槛。

`npm run eval:reuse` 是离线影子测试。使用红酒表产生候选，用同源、不重叠的白酒表验证，另有 8 个公开负向表和 2 个合成边界输入。这一张白酒留出表的两处待匹配字段，精确匹配命中 1 处，影子规则命中 2 处并检查了 4,898 行。模拟运行少一次澄清，人工用时未测。10 个负向输入均未触发。由于正向留出只有 1 批，候选保持停用。[影子试验记录](evidence/reuse-shadow.json)

`npm run check:graph` 用 Chrome 逐项核对运行日志、`plan.json` 与球体渲染器的高亮集合，覆盖两条不同链路和单位缺失。仓库的 GitHub Actions 配置已加入此检查。[图谱核对记录](evidence/graph-ci.json)
